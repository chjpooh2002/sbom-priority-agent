# 오픈소스 취약점 조치 우선순위 에이전트

취약점 스캐너는 수십~수백 건의 경보를 쏟아내지만, 그중 이 서비스에 실제로 위험한 것은 일부다.
이 프로젝트는 스캔 결과를 받아 **실제로 급한 것만 위로 올리고, 고칠 방법까지 붙여 주는** 에이전트다.

## 구조

```
빌드 결과물(jar)
  → 구성 요소 목록(SBOM) 생성 ·········· syft
  → 알려진 취약점 대조 ·················· grype
  → 외부 지표 보강 ······················ 악용 가능성 점수(EPSS), 실제 악용 확인 목록(CISA KEV)
  → 코드 사용 여부 ······················ 우리 코드가 해당 라이브러리를 직접 가져다 쓰는지
  → 1차 규칙 판정 ······················· 숫자로 정할 수 있는 건 언어 모델에 맡기지 않는다
  → 2차 에이전트 판정 ···················· 코드·설정을 직접 읽어 공격 경로 확인, 근거 있을 때만 판정 조정, 조치안 작성
  → 보고서 + 판단 근거 기록
```

설계 원칙

1. **역할 분리**: 점수 계산은 규칙이, 맥락 판단(프레임워크 내부 사용, 공격 전제 조건 성립 여부, 입력 흐름)은 에이전트가 맡는다.
2. **근거 강제**: 에이전트는 정해진 출력 형식으로만 답하고, 판정을 바꿀 때는 파일 경로와 줄 번호를 근거로 남겨야 한다.
3. **측정 가능**: 사람이 먼저 매긴 정답과 비교해 세 방식(심각도 점수만 / 규칙 / 규칙 + 에이전트)의 정확도를 같은 표로 낸다.
4. **안전한 도구**: 에이전트는 프로젝트 폴더 안 파일을 읽기만 할 수 있다.

## 실행

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
brew install syft grype            # 윈도우는 각 도구 배포 페이지 참고
export JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-17.0.16.8-hotspot"   # JDK 17 필요 (윈도우 Git Bash 예시, 경로는 설치 위치에 맞게)

# 1) 스캔
bash scripts/scan.sh sample-app out

# 2) 규칙 판정만 먼저 (API 키 불필요)
PYTHONPATH=src python -m sbom_agent.cli run --scan out/grype.json --src sample-app --out out --no-agent

# 3) 정답 표 작성: 결과 파일을 보기 전에 직접 판단해서 채운다
PYTHONPATH=src python -m sbom_agent.cli gold --results out/results.json --out eval/gold.csv

# 4) 에이전트까지 실행
export OPENAI_API_KEY=...
export OPENAI_MODEL=...            # 사용할 모델 이름
PYTHONPATH=src python -m sbom_agent.cli run --scan out/grype.json --src sample-app --out out

# 5) 정확도 비교
PYTHONPATH=src python -m sbom_agent.cli eval --results out/results.json --gold eval/gold.csv
```

## 예제 서비스 (`sample-app/`)

측정용으로 오래된 의존성을 일부러 고정한 스프링 부트 서비스다. 배포하지 않는다.

| 상황 | 의도 |
| --- | --- |
| 요청 헤더를 그대로 로그에 기록 | 직접 사용 + 외부 입력 도달 |
| 사용자 입력을 문자열 치환기에 전달 | 직접 사용 + 외부 입력 도달 |
| 요청 값을 객체에 바인딩, jar 형태로 실행 | 프레임워크 내부 사용, 공격 전제 조건 일부 불성립 |
| 선언만 하고 쓰지 않는 라이브러리 | 심각도는 높지만 실제 위험은 낮음 |
| 개발용 데이터베이스, 웹 콘솔 꺼짐 | 설정으로 공격 경로 차단 |

## 정답 작성 기준

| 등급 | 기준 |
| --- | --- |
| P1 긴급 | 외부 입력이 취약 기능에 닿고, 실제 악용 사례가 있거나 악용이 쉬움. 이번 주 조치 |
| P2 높음 | 공격 경로가 있으나 조건이 붙음. 다음 배포에 포함 |
| P3 보통 | 경로가 확인되지 않거나 전제 조건이 성립하지 않음. 정기 업데이트 때 |
| P4 낮음 | 코드와 프레임워크 어디서도 쓰이지 않음. 기록만 |

## 한계

- 코드 사용 여부는 가져오기 문장 기준이라, 리플렉션이나 설정만으로 쓰이는 경우는 에이전트 판단에 기댄다.
- 정답은 한 사람이 매긴 것이라 기준에 따라 달라질 수 있다.
- `fixtures/` 의 점수는 동작 확인용 가짜 값이다. 측정에는 실제 스캔 결과만 쓴다.
