# 최종 정확도 비교 (정답 v1 / v2)

- 재채점일: 2026-11-04. 새 판정은 하지 않았다. 2차 측정에서 이미 만든 판정 결과를 정답 v1과 v2로 각각 다시 채점했고, API는 호출하지 않았다.
- 판정 결과 파일: `out/v2/gpt-6-luna/results.json`, `out/v2/gpt-6-sol/results.json`(45건 판정), `out/v2/gpt-6-luna-all/results.json`(132건 전체 판정). 판정 방식은 `eval/result_v2.md`와 같다.
- 정답
  - v1: `eval/gold_val15.csv`(379a023, 결과를 보기 전에 고정), `eval/gold30.csv`(1차 정답)
  - v2: `eval/gold_val15_v2.csv`, `eval/gold30_v2.csv`(94614e4). README 기준(기능 단위)과 실행 확인(`eval/fact_checks.md`)을 다시 적용했다. 바뀐 행은 `eval/gold_changes.md`에 있다.
- 채점 도구: `python -m sbom_agent.cli eval`(그대로). v1로 채점한 수치는 `eval/result_v2.md`와 모두 같았다(재현 확인).
- 지표 정의: "급한 건"은 정답이 P1·P2인 건이다. "불필요한 긴급 경보"는 정답이 P3·P4인데 P1·P2로 판정한 건이다.

## 해석할 때 주의할 점

1. **v2 정답은 v1 결과를 본 뒤에 고쳤다.** 고친 근거는 사실 확인(실행 jar 확인, 취약 기능 사용 여부)이지만, 결과를 모르는 상태에서 매긴 정답이 아니다. 그래서 v2 수치는 v1 수치보다 측정 오염 가능성이 크다. 두 수치를 함께 적는다.
2. **검증 세트 v2에는 급한 건(P1·P2)이 하나도 없다**(P3 12건, P4 3건). 그래서 v2 검증 세트로는 "급한 건 놓치지 않은 비율"을 잴 수 없다. 이 지표는 gold30(개선에 쓴 세트, 참고용)에서만 나온다. 이 지표를 v2 기준으로 일반화해서 말할 근거는 없다.
3. 검증 세트 v2에서는 정답이 모두 P3·P4이다. 그래서 등급을 낮게 매길수록 유리하고, 에이전트는 주로 등급을 낮추는 쪽으로 바꿨다(아래 지표 참고). 정확도 상승 중 일부는 이 구성 때문일 수 있다.
