# 정답 v1 → v2 변경 내역

- v2 판정 기준: README 기준(기능 단위)으로 확정했다. 취약 기능이 실제로 쓰이는지 사실을 확인한 뒤 기준을 다시 적용했다. 사실 확인 근거는 `eval/fact_checks.md`에 있다.
- 작성 시점: v1 결과(1·2차 측정)를 본 뒤에 고쳤다. v2 정답으로 낸 수치는 결과를 모르는 상태에서 매긴 정답 기준이 아니다.
- v1 파일(`gold30.csv`, `gold_val15.csv`)은 바꾸지 않았다. key, vuln_id, package, version은 v1과 v2가 30행·15행 모두 같다.
- 메모는 사람이 쓴 v2 메모를 그대로 옮겼다. v2 메모 안에 v1 메모가 함께 들어 있다.

## 형식 수정 (내용 변경 없음)

v2 메모 세 개에 쉼표가 있는데 따옴표로 감싸지 않아, CSV가 7칸으로 읽혔다. 해당 메모 칸 앞뒤에 큰따옴표만 추가했다. 대상은 `gold30_v2.csv`의 CVE-2021-44228·CVE-2021-44832, `gold_val15_v2.csv`의 CVE-2016-1000027이다. 고치기 전후 바이트를 비교해 추가된 것이 따옴표뿐임을 확인했다. gold_tier와 메모 글자는 바뀌지 않았다.

## 사실 확인 기록과 표현이 다른 점 (메모는 그대로 둠)

log4j 세 행의 메모에는 "log4j-core 클래스는 로드되지 않음"이라고 적혀 있다. `fact_checks.md`의 기록은 이보다 좁다. 제공자를 비교하는 단계에서 log4j-core의 팩토리·선택기 계열 클래스 13개는 로드됐고, `LoggerContext`, `Logger`, lookup 클래스가 로드되지 않았다. 로그 처리를 log4j-to-slf4j(logback)가 맡는다는 결론은 같다.
