# 작업기록

### 2026-11-02 · 빌드 환경을 JDK 17 + Gradle 7.6.4로 고정
- 상황: `scan.sh`가 시스템 `gradle`에 의존했는데 설치돼 있지 않았고, `sample-app`에 `gradlew`도 없었다. PATH 기본 JDK는 21인데, JDK 21을 지원하는 Gradle(8.5 이상)은 Spring Boot 2.6.5 플러그인 지원 범위(7.x까지)를 벗어난다.
- 판단: (1) Gradle 7.6.4 + JDK 17로 맞추기, (2) 최신 Gradle + JDK 21로 가되 Boot 버전 올리기, (3) 1번에 `gradlew`까지 커밋하기, 셋을 비교했다. 2번은 일부러 고정한 취약 의존성이 바뀌어 측정 대상이 달라지므로 제외했다. 다른 환경에서도 같은 빌드가 나오도록 3번을 골랐다. JDK 경로는 사람마다 다르므로 저장소에 쓰지 않고, `scan.sh`에서 주 버전만 확인해 17이 아니면 멈추게 했다.
- 변경: `sample-app/gradlew`, `sample-app/gradlew.bat`, `sample-app/gradle/wrapper/*`, `scripts/scan.sh`, `README.md`, `.gitattributes`(CRLF 변환으로 `gradlew`·`*.sh`가 깨지지 않게 LF 고정)
- 결과: JDK 17에서 빌드·스캔 성공(약 2분 30초, grype DB 첫 다운로드 포함). SBOM 구성 요소 35개, grype 매칭 132건. JDK 21일 때는 안내 문구를 출력하고 exit 1로 멈추는 것을 확인했다. 사용 도구는 syft 1.54.1, grype 0.121.0(DB 2026-11-01 빌드)이다.

### 2026-11-02 · 보고서 출력 코드의 Python 3.11 문법 오류 수정
- 상황: `cli.py` 보고서 표에서 f-string 안에 같은 따옴표를 쓰는 중첩 f-string이 있었다(3.12 이상에서만 허용). Python 3.11.9에서 모듈을 불러오는 단계에서 SyntaxError가 나서 `run` 자체가 실행되지 않았다.
- 판단: Python 3.12를 설치하는 대신 코드를 고쳤다. 고칠 곳이 한 줄이고, 최소 버전 표기가 없어 다른 환경에서도 같은 문제가 날 수 있기 때문이다. 중첩 f-string을 `format(r['epss'], '.3f')`로 바꿨고, 판정 로직은 건드리지 않았다.
- 변경: `src/sbom_agent/cli.py`
- 결과: `--no-agent` 실행 성공. 132건, 라이브러리 21종. EPSS는 132건 모두 실제 값으로 채워졌다(fixtures 미사용).
